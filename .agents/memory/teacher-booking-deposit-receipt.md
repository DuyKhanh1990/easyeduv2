---
name: Teacher booking deposit receipt
description: Accounting design for student-selected teacher bookings funded from the deposit wallet.
---

For student-selected bookings, save only the exact dates and shifts the student chose. Group identical package products for the same student and location across paid invoices and deposit-funded credits; show one aggregate entitlement (for example, 2 booked of 20 total) while preserving the underlying purchase and price records for accounting. For previously paid per-session packages, invoice-item quantity is session entitlement; the catalog package may be configured as one session to represent unit price. Enforce aggregate available entitlement, including active holds, rather than the catalog's session count.

Payments categorized as “Học phí theo đăng ký” are still tuition: when paid, their tuition portion must credit the Học phí wallet so attendance can deduct it normally. Wallet accounting must recognize this category consistently for direct payments and installment schedules.

The “Ví Đặt Cọc” payment label does not itself move balances. For this self-booking flow, do not create an automatic zero-due invoice. When an eligible session is finalized, atomically debit its session amount from “Đặt cọc” and credit the same amount to “Học phí”; cancelled or still-pending sessions cause no transfer. Record the package entitlement and transfer independently of invoices so aggregate package counts remain correct. Attendance uses the established tuition-wallet deduction path and each session keeps its applicable unit price.

When cancellation lead time Y=0, confirmation immediately finalizes the booking using the applicable package or deposit flow; there is no deferred hold window. When Y>0, confirmation first creates only a cancellable reservation/slot hold. It must not yet create official 1-1 class/session records or wallet movements. For a previously paid package, cancellation before the configured deadline releases the hold without consuming package sessions. If the deadline passes, create the tutor session and consume the reserved package entitlement; attendance follows ordinary tuition-wallet deduction. For a deposit-funded booking, cancellation before the deadline leaves both wallets unchanged. If the deadline passes, create the tutor session and transfer only that session's applicable amount from deposit to tuition, without an invoice.

For fixed student/teacher/date/shift sessions, prefer `classType: "tutor"` over free class: tutor classes use the normal `class_sessions` and `student_sessions` attendance and finance paths, while free classes have a distinct day-registration model.

Only paid or confirmed invoices categorized “Học phí theo đăng ký” should supply packages to this self-booking flow. Count only sessions booked through this flow against those packages; ordinary class history shares the same catalog package ID and must not consume this separate entitlement.

One booking request may contain multiple shifts across different dates. Changing the focused calendar date must preserve the other selected date/shift pairs; validate every date. Merge paid purchases of the same package product into one selectable aggregate, including new ten-session purchases of an already-listed package. Reuse one tutor class for the same student, location, and package product across booking batches; teacher assignment belongs to each session and is not a class-matching key. With Y>0, finalize each eligible session at its own cutoff and append it to the same class; with Y=0, finalize all selected sessions immediately.

**Why:** The user wants learners to pick available shifts on several days before submitting once and continue scheduling remaining sessions in later batches. This extends the existing partial-package rule: unbooked sessions remain available for later scheduling, and all booked dates must still share the selected center. The user specified immediate finalization when Y=0, reservation-only behavior until the cancellation deadline when Y>0, aggregate counts for identical packages, per-session teacher assignment, and no automatic deposit-funded receipt.

**How to apply:** Keep each pre-deadline reservation separate from official class and wallet records. Count active holds against available slots and aggregate package entitlement without showing them as finalized sessions; cancellation releases the hold. At finalization, atomically link the exact session, package usage/credit, and any deposit-to-tuition transfer. Resolve the tutor class by student/location/package product, not teacher or invoice; create it only if it does not yet exist, and append eligible sessions from later batches. Keep teacher IDs on each session. Preserve source purchase and unit-price history even while presenting one aggregate package count. For multi-date booking, validate each selected day independently and persist all chosen date/shift pairs together.
