---
name: Teacher booking deposit receipt
description: Accounting design for student-selected teacher bookings funded from the deposit wallet.
---

For the immediate student-selected booking flow, save only the exact dates and shifts the student chose. A 10-session package can be paid in full and have 2 sessions booked now, leaving 8 available to schedule later. A previously paid package creates no new receipt; only its remaining sessions at the selected center are consumed by new bookings. For a previously paid per-session package, invoice-item quantity is the session entitlement; the catalog package may be configured as one session only to represent the unit price. Enforce the remaining invoice quantity, not the catalog session count. A new package uses its configured total price and session count, requires enough deposit balance for the entire package, and creates one receipt under “Học phí theo đăng ký” with the full tuition amount and an equal deposit deduction.

Payments categorized as “Học phí theo đăng ký” are still tuition: when paid, their tuition portion must credit the Học phí wallet so attendance can deduct it normally. Wallet accounting must recognize this category consistently for direct payments and installment schedules.

The “Ví Đặt Cọc” payment label does not itself move balances. In the same transaction as the receipt and booking, debit “Đặt cọc” and credit “Học phí” once; do not perform another transfer or count the deposit as new cash income. Keep attendance on the established wallet deduction path and store a per-session price consistent with the package's actual paid amount.

When cancellation lead time Y=0, confirmation immediately finalizes the booking using the applicable package or deposit flow; there is no deferred hold window. When Y>0, confirmation first creates only a cancellable reservation/slot hold. It must not yet create official 1-1 class/session records, tuition receipts, or wallet movements. For a previously paid package, hold the selected session entitlement separately; cancellation before the configured deadline releases it without consuming package sessions. If the deadline passes, create tutor class/session records and consume the reserved package sessions; attendance then follows the ordinary tuition-wallet deduction path. For a deposit-funded booking, cancellation before the deadline leaves deposit and tuition wallets unchanged. If the deadline passes, create tutor class/session records and an automatic “Học phí theo đăng ký” receipt; offset the full tuition from the deposit wallet, credit the tuition wallet by the same amount, and leave zero due. Attendance then deducts from the tuition wallet normally.

For fixed student/teacher/date/shift sessions, prefer `classType: "tutor"` over free class: tutor classes use the normal `class_sessions` and `student_sessions` attendance and finance paths, while free classes have a distinct day-registration model.

Only paid or confirmed invoices categorized “Học phí theo đăng ký” should supply packages to this self-booking flow. Count only sessions booked through this flow against those packages; ordinary class history shares the same catalog package ID and must not consume this separate entitlement.

One booking request may contain multiple shifts across different dates. Changing the focused calendar date must preserve the other selected date/shift pairs; validate every date. Paid invoice-item packages are separate purchase buckets and must appear separately in the package selector. Reuse one tutor class for later booking batches that select the same purchase bucket and same student/teacher/location; append eligible sessions to that class and code. A new 10-session invoice is a distinct purchase bucket and gets a distinct tutor class, even if it uses the same catalog package. With Y>0, finalize each eligible session at its own cutoff and append it to that bucket's class; with Y=0, finalize all selected sessions immediately.

**Why:** The user wants learners to pick available shifts on several days before submitting once and continue scheduling remaining sessions in later batches. This extends the existing partial-package rule: unbooked sessions remain available for later scheduling, and all booked dates must still share the selected center. The user specified immediate finalization when Y=0, reservation-only behavior until the cancellation deadline when Y>0, reuse of the class tied to the selected paid purchase, and a separate class for each new invoice/purchase.

**How to apply:** Keep each pre-deadline reservation separate from official class, invoice, and wallet records. Count active holds against available slots and purchase-bucket entitlement without showing them as finalized sessions; cancellation releases the hold. At finalization, atomically link exact sessions, any receipt, package consumption, and paired wallet entries. Resolve the tutor class by the selected invoice-item purchase bucket plus student/teacher/location; create it only if that bucket has no class yet. Append eligible sessions from later batches to the same class. Preserve each invoice's full package quantity while counting finalized self-booked sessions against that purchase bucket's remaining entitlement. For multi-date booking, validate each selected day independently and persist all chosen date/shift pairs together.
