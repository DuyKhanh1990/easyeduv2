# New-center database bootstrap

Argo runs `db-bootstrap-job.yaml` before the app Deployment. Kustomize applies the
same `images.newTag` to both resources, so the schema is generated by the app image
selected for that release.
The Job is opt-in to avoid changing existing centers during ordinary syncs.

For a new center, the center-creation workflow must:

1. Put `DB_BOOTSTRAP_ENABLED: "true"`, the center's `DATABASE_URL`, and
   `STAFF_LIMIT` (positive integer) in `easyeduv2-config`. The database name is
   taken only from that URL.
2. Create the `easyeduv2-bootstrap` Kubernetes Secret with
   `BOOTSTRAP_ADMIN_PASSWORD` (at least 12 characters).
3. Update the single `images.newTag` value in `kustomization.yaml` to the image tag
   selected for the Deployment.

The seeder is explicitly pointed at the same `DATABASE_URL` used by the migration
runner, even if the ConfigMap also contains another app URL. The bootstrap role in
`DATABASE_URL` must be able to create databases, or the
center ConfigMap can provide a separate `DB_BOOTSTRAP_URL` for the maintenance
connection. `DB_OWNER_ROLE` optionally selects the new database owner.

The external `deploy-easyedu` / `create-center.sh` repository is not present in
this workspace, so its ConfigMap/Secret generation must be updated there before
new centers can opt in.
